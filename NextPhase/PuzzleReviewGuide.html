ArrayPatchPuzzle — Minimum patches to add so every value in [1, n] is formable as a subset sum of the array.

Tags. Tier 2 arrays tricky edges

Java file. JavaTest\src\puzzle\arrays\ArrayPatchPuzzle.java

Issue statement. Minimum patches to add so every value in [1, n] is formable as a subset sum of the array.

Current Java approach. Greedy (composePatch2) on a sorted array: keep upper as the smallest sum not yet formable; if the next number is within reach, extend coverage, otherwise patch with upper itself and double the reachable range.

Time / Space Complexity. Time O(n + log n), Space O(1). (composePatch1 is an older non-optimal alternate.)

Better solution to know. The greedy range-expansion method already present is the asymptotically right solution to know.

Silent preconditions. The greedy proof assumes the input array is sorted and that values are non-negative.

Canonical sample output. For [1,3] and n=6, one patch 2 is enough to cover the full range [1,6].

Common interview follow-up. Why is patching exactly upper always optimal? What changes if the input is not sorted?

One-minute recall. Track the smallest missing sum upper. If the next value is at most upper, coverage extends; otherwise patch with upper itself.

Comparison details. The greedy method beats brute-force subset reasoning because it tracks one continuous covered range rather than individual subset sums. The whole proof reduces to maintaining the invariant that every value in [1, upper-1] is already formable.

How to think about this issue. Common themes: two-pointers, greedy local decisions, in-place state mutation, and hidden preconditions such as sorted input or non-negative numbers.

Tags. Tier 2 arrays

Java file. JavaTest\src\puzzle\arrays\BalanceArrayPuzzle.java

Issue statement. Given two equal-length arrays, swap elements to minimize the difference between their sums.

Current Java approach. Recursive brute-force / backtracking over swap decisions; the file also includes an exact-cardinality subset-sum DP with reconstruction of one optimal split.

Time / Space Complexity. Brute force is exponential; the DP is pseudo-polynomial in the total absolute sum.

Better solution to know. If you only need the optimum value (or one reconstructed optimum split), prefer the exact-cardinality subset-sum DP over brute-force search on larger inputs.

Canonical sample output. A good way to read the DP version is: from the combined 2n numbers, choose exactly n numbers whose sum is as close as possible to half of the total.

Common interview follow-up. How do you reconstruct the actual split after finding the best achievable DP state?

Comparison details. Brute-force swapping is useful for understanding the problem, but it repeats equivalent states heavily. The stronger DP changes the viewpoint: it is no longer “which swaps do I do?” but “which n values belong to one side of the split?”

Backtracking / DFS / Search

Keep the choose → recurse → undo shape visible in Python too.

def dfs(state):\n    if done(state):\n        return True\n    for choice in choices(state):\n        if not valid(state, choice):\n            continue\n        apply(state, choice)\n        if dfs(state):\n            return True\n        undo(state, choice)\n    return False
