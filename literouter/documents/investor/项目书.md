# 项目书：面向 AI Agent 时代的智能 LLM 网关

**日期：** 2026-11-12
**版本：** 1.0（基于内部架构设计文档 Doc 01–04 整理）
**状态：** 投资沟通材料，数据为内部设计目标与假设

---

## 一、一句话定位

我们为 AI Agent（尤其是长时程编程任务）提供**统一、可靠、可计费、会"挑模型"的 LLM 网关**——让 Agent 开发者不必关心"用哪家模型、怎么省钱、怎么不出错、怎么收钱"。

## 二、市场机会：Agent 爆发带来的基础设施缺口

AI 编程助手与自主 Agent 正在从"单轮问答"演变为**持续数小时、包含规划—编码—测试—调试的长时程任务**。这类任务有两个结构性变化：

1. **模型调用次数爆炸**：一个编程任务可能包含几十到几百次 LLM 调用，跨越多个阶段，每个阶段对模型的能力要求完全不同（规划需要推理、调试需要代码理解、审查需要长上下文）。
2. **成本与可靠性成为核心痛点**：固定使用一个高价模型，成本失控；固定使用低价模型，任务成功率下降。同时，多 Provider 的接入、超时、限流、计费、对账等工程问题消耗大量研发资源。

现有方案（直接使用单一 Provider SDK，或简单的 API 转发网关）都没有解决"**按任务阶段智能选模型**"和"**企业级计费可靠性**"这两个问题。这正是我们的切入点。

## 三、产品：智能 LLM 网关

### 3.1 核心能力

**统一接入。** 一个 OpenAI 兼容 API，屏蔽 OpenAI、Anthropic、Google、Bedrock、DeepSeek、自托管推理（vLLM/SGLang）等所有 Provider 差异。

**智能路由。** 基于模型能力注册表（上下文窗口、工具调用、结构化输出等硬约束）与策略引擎，结合成本、延迟、健康度做路由决策；支持按编程任务阶段（规划、探索、生成、调试、审查）感知地选择模型。

**任务感知。** 网关能识别多个请求属于同一个长时程任务（Task/Session 关联），在任务内保持模型连续性、按需安全切换，并聚合任务级成本与效果指标——这是与通用转发网关的本质区别。

**企业级计费。** 预付费钱包 + 资金预留 + 幂等结算 + 不可变复式账本。核心设计保证：**任何网络超时、服务崩溃、事件重复，都不会产生重复扣费或资金错账**。

### 3.2 关键差异化

| 维度 | 通用 API 转发网关 | 我们的网关 |
|---|---|---|
| 选模型 | 静态配置/简单负载均衡 | 阶段感知 + 能力匹配 + 成本/质量权衡 |
| 长任务支持 | 无概念 | Task/Session 关联、连续性、任务级成本归因 |
| 计费可靠性 | 简单计数 | 预留-结算事务、复式账本、防重复扣费 |
| 故障处理 | 超时即重试 | 未知结果不盲目重试，进入对账恢复 |
| 效果衡量 | 按 token 计价 | **按"每个成功任务的成本"衡量和优化** |

## 四、商业模式

- **按用量计费（Pay-as-you-go）**：客户对逻辑模型付费（如输入/输出 token 单价），平台按实际 Provider 成本结算，赚取差价（毛利 = 客户收费 − Provider 成本）。
- **路由优化即利润杠杆**：智能路由在保持任务成功率的前提下降低成本，直接扩大毛利空间——路由算法就是我们的利润引擎。
- **企业版扩展**：组织级钱包与预算、合规区域路由、审计、专属定价等，为后续企业销售铺路。

## 五、技术护城河

我们的架构设计在同类产品中少见的严谨，形成三层壁垒：

1. **财务正确性**：预留-结算-账本的事务与幂等设计（Doc 02/03），经受住并发超支、崩溃恢复、重复事件等故障注入测试后，达到可处理真实资金的标准——这是大多数开源网关不具备的。
2. **任务感知路由**（Doc 04）：Gateway 只负责模型调用，Agent Runtime 负责任务编排——清晰的边界让我们与所有 Agent 框架兼容，同时积累"哪个模型在哪个编程阶段效果最好"的独家数据。
3. **数据飞轮**：任务级反馈（测试通过率、任务成功率）回流到路由策略，用得越多，路由越准，成本-效果比越好，竞品越难追。

## 六、实施路径与里程碑

- **Phase 1–2（地基）**：多 Provider 接入、路由引擎、请求可靠性。
- **Phase 3–4（计费核心）**：预留、结算、账本、恢复机制。
- **Phase 5（上线闸门）**：通过并发、故障注入、安全审查后才能接入真实资金——体现我们对可靠性的承诺。
- **Phase 6（增长）**：任务感知路由、成本/毛利分析、效果基准测试，用数据证明"同等效果更低成本"。

**MVP 验证目标**：在受控基准测试中，智能路由策略相比静态选模型，在成本、质量、延迟或可靠性上至少一项有可度量的提升。

## 七、为什么是现在

- 模型市场高度碎片化且持续演化，客户需要"与 Provider 解耦"的保险。
- Agent 应用从演示走向生产，计费、合规、可靠性从"可有可无"变成"刚需"。
- 编程是第一个被验证的高价值 Agent 场景，成本优化空间巨大，且效果可度量（测试通过率）。

## 八、风险与应对

| 风险 | 应对 |
|---|---|
| 客户不传任务元数据，智能路由无从发挥 | 无元数据时退化为高质量通用路由；提供 SDK 降低集成成本；用"任务级成本看板"作为集成激励 |
| Provider 自建网关/降价 | 我们的价值在跨 Provider 中立性与任务级优化，单一 Provider 无法提供 |
| 计费错误损害信任 | 复式账本 + 发布闸门 + 不可变审计，把财务正确性作为第一优先级 |
